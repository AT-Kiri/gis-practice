# AI Agent 多智能体架构决策 ADR-003

## 1. 状态

**已接受**（Accepted）

## 2. 背景

项目需要一个 AI 应急助手，能够：
- 理解用户的自然语言查询
- 自动调用 GIS 工具完成任务
- 返回结构化的结果和地图渲染

## 3. 决策

采用**多智能体协同**架构，通过 **SSE（Server-Sent Events）** 事件流实现前后端通信。

## 4. 架构设计

### 4.1 多智能体角色

| 角色 | 职责 |
|------|------|
| **Coordinator（协调者）** | 意图分类、任务规划、步骤调度 |
| **Search Agent（检索专家）** | 执行空间查询、要素搜索 |
| **Analysis Agent（分析专家）** | 执行缓冲区分析、网络分析 |
| **Route Agent（路径专家）** | 执行路径规划、路线分析 |
| **Knowledge Agent（知识专家）** | 回答 GIS 知识问题 |

### 4.2 SSE 事件流

```
用户发送消息 → 建立 SSE 连接 → 接收事件流 → 更新 UI
```

| 事件 | 说明 |
|------|------|
| `onIntentClassified` | 意图分类结果 |
| `onPlanCreated` | 任务计划 |
| `onStepStart` | 步骤开始 |
| `onStepDone` | 步骤完成 |
| `onToolStart` | 工具调用开始 |
| `onToolResult` | 工具调用结果 |
| `onText` | 流式文本 |
| `onAgentEnd` | 全部完成 |
| `onError` | 错误信息 |

## 5. 后果

### 5.1 正面

- 任务分解清晰，职责单一
- 流式响应用户体验好
- 易于扩展新的 Agent 类型

### 5.2 负面

- 多智能体协调复杂度高
- SSE 连接管理需要额外处理

## 6. 替代方案

| 方案 | 未选理由 |
|------|---------|
| 单 Agent | 任务复杂度高，难以维护 |
| WebSocket | SSE 更轻量，单向通信足够 |
| REST 轮询 | 实时性差，用户体验不好 |
